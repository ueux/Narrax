# `data/` — local data

**Nothing in this directory's contents is committed.** Only this README is tracked
(`.gitignore` ignores `data/*` but re-includes `data/README.md`).

Local datasets are not source code: they are large, sometimes sensitive, and always
reproducible from the pipeline. Keeping them out of git keeps the repository small and
avoids accidentally publishing collected content.

## Intended layout

```text
data/
├── README.md          # this file (tracked)
├── raw/               # (ignored) verbatim source payloads, if cached to disk
├── interim/           # (ignored) intermediate exports between stages
└── exports/           # (ignored) evaluation sets, report artifacts
```

## Rules

1. **Source truth lives in PostgreSQL, not here.** This directory is for scratch/cached
   artifacts only; the database is the system of record (docs/architecture.md §2.2).
2. **Never commit collected content.** It may contain pseudonymous user handles and is
   subject to the data boundaries in [../docs/data-safety.md](../docs/data-safety.md).
3. **Never commit secrets.** No `.env`, tokens, or API keys — anywhere, but especially here.
4. **Evaluation sets that must be reproducible** should be generated by a documented script
   in [`../scripts/`](../scripts/) and stored in `experiments/` or exported as a report
   artifact — not hand-curated here.

## Reproducing from scratch

`data/` should always be reconstructible:

```bash
docker compose up -d          # start PostgreSQL + pgvector
cd backend && alembic upgrade head
# then run ingestion for a topic (Phase 1+)
```
